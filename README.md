# نقش داده و ارزیابی — مسیریابی شهری شیراز

این بسته برای نقش «داده و ارزیابی» تهیه شده و با فایل‌های واقعی گروه کار می‌کند.

## ساختار مورد انتظار ورودی‌ها
فایل‌های خام گروه را در مسیرهای زیر قرار دهید:
- `data/raw/shiraz_drive.graphml`
- `data/raw/shiraz_2d_grid.npy`

فایل‌های خام را بازنویسی نکنید. اسکریپت، نسخه‌های تحلیلی و گزارش‌ها را در `results/` تولید می‌کند.

## نصب
```bash
pip install -r requirements.txt
```

## اجرا
```bash
python scripts/prepare_and_evaluate.py --graph data/raw/shiraz_drive.graphml --grid data/raw/shiraz_2d_grid.npy --out results --pairs 25
```

## خروجی‌ها
- `data_quality_summary.csv`: شاخص‌های کیفیت داده
- `quality_report.json`: گزارش ماشینی کامل
- `nodes_prepared.csv`: جدول گره‌ها با مختصات عددی
- `edges_clean.csv`: یال‌های معتبر برای تحلیل با حفظ جهت و کلید یال موازی
- `route_evaluation.csv`: آزمون مسیرهای نمونه با دایکسترا و وزن طول
- `data_preparation_evaluation_report.md`: گزارش فارسی برای تحویل

## تصمیم‌های مهم
- گراف اصلی باید جهت‌دار و چندگرافی باقی بماند؛ خیابان یک‌طرفه و یال‌های موازی نباید حذف شوند.
- برای وزن پایه از `length` بر حسب متر استفاده شده است؛ داده ترافیک زنده در ورودی وجود ندارد.
- مقدارهای گمشده در ویژگی‌های اختیاری با حدس پر نمی‌شوند.
- گرید پروژه طبق مستند طراحی: `1=خیابان/قابل عبور` و `0=غیرخیابان`.
- برای مسیریابی گرافی، یال‌های نامعتبر در نسخه تحلیلی کنار گذاشته می‌شوند، اما فایل خام دست‌نخورده می‌ماند.

## تفکیک داده آزمایش
در مسیریابی، تقسیم تصادفی ردیف‌های گراف به train/test معمولاً معنای مناسبی ندارد؛ زیرا ممکن است اتصال شبکه را خراب کند. به‌جای آن، مجموعه ثابتی از جفت‌های مبدأ-مقصد برای آزمون الگوریتم‌ها استفاده می‌شود. اسکریپت جفت‌ها را با seed ثابت از بزرگ‌ترین مؤلفه قویاً همبند انتخاب می‌کند. هنگام مقایسه Dijkstra و A*، دقیقاً همین جفت‌ها باید برای هر دو الگوریتم استفاده شوند.
